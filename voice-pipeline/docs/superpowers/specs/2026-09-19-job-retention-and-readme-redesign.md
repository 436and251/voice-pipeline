# Job 生命周期与双仓 README 整改设计

## 背景

AudioMiner 以可选模块方式调用 voice-pipeline。AudioMiner 创建并管理
`<voice-pipeline>/jobs/<job_id>/`，voice-pipeline 在这些目录中读取任务描述、写入事件，
并由 AudioMiner 保存子进程日志。当前成功任务只会删除 stdout/stderr 并压缩部分进度事件，
不会淘汰整个 job；失败、推理及历史测试任务也没有统一生命周期。结果是 job 目录持续累积，
部分运行文件还曾被提交到 Git。

两个仓库的 README 也混有过多历史设计说明，安装、连接、完整工作流和磁盘生命周期不够集中。

## 目标

1. `jobs/` 永远不进入版本库。
2. 运行文件按业务生命周期自动清理，不影响断点继续、候选试听和人工晋升。
3. 不在用户不知情的目录中无限积累日志和临时请求。
4. 保留正式模型、未晋升候选、评测试听、最终推理 WAV 和用户数据。
5. 重写两个仓库的入口文档，使用户可以从源码部署并完成素材挖掘到推理的完整流程。

## 非目标

- 不改变 AudioMiner 当前素材处理缓存策略。
- 不自动删除共享模型缓存、虚拟环境、训练数据或正式模型。
- 不自动删除尚未人工晋升的候选和对应评测结果。
- 不新增通用磁盘配额、后台守护进程或数据库。
- AudioMiner 的 `docs/` 继续保持本地私有，不纳入远端版本管理。

## 清理所有权

Job 清理由 AudioMiner 负责。它是 job 的创建者，掌握当前活动子进程、目标人、操作类型和
GUI 生命周期；将相同判断再放入 voice-pipeline 会形成重复规则，并可能在宿主尚未消费事件时
提前删除文件。

voice-pipeline 只负责：

- 正确写入结构化终态事件；
- 在人工晋升后清理 `runs/<目标人>` 中不再需要的原始训练产物；
- 忽略并取消跟踪 `jobs/` 运行目录。

## Job 状态分类

清理器只处理 `<module_root>/jobs/` 的直接子目录。所有路径在读取或删除前必须解析并确认仍位于
该目录内；符号链接、越界路径、过大的描述文件和无法解析的状态不得自动删除。

### 必须保留

- 当前 AudioMiner 正在执行的 job。
- 没有可靠终态、可能因 GUI 或系统退出而中断的 job。
- 已完成训练与评测，但尚未出现 `promotion_completed` 的候选 job。
- 每个目标人在最近 48 小时内最新的一份失败 job。

候选 job 被视为“业务流程未完成”，即使训练子进程已经成功退出，也必须保留到人工晋升完成。

### 必须删除

- 已成功晋升的训练 job。
- 已完成的推理临时 job 和其请求快照；最终 WAV 位于 `outputs/`，不受影响。
- 取消且不再活动的 job。
- 超过 48 小时的失败 job。
- 同一目标人除最新失败 job 之外的其他失败 job，即使仍未满 48 小时。
- 已成功完成、无需候选选择或继续操作的其他终态 job。

失败期限使用终态事件的 UTC 时间；事件时间无效但 job 可安全识别时使用 job 目录最后修改时间。
不能可靠确定时间或身份时保留并报告，不猜测删除。

## 触发时机

清理器在以下时机运行：

1. AudioClone Studio 启动、训练模块握手成功后；
2. 训练、晋升或推理子进程结束且 AudioMiner 已消费完结构化事件、关闭日志文件后。

清理器接受当前活动 job 作为保护项。清理异常不得使应用启动或已完成任务失败；Activity 只显示
一条汇总，包含删除数量、保留的可恢复失败任务数量，以及无法判断而保留的目录数量。

## Git 与存储边界

### voice-pipeline

- 忽略 `/jobs/`、`/runs/`、`/outputs/`、`/models/`、Python 缓存和本地虚拟环境。
- 从 Git 索引移除历史 job 文件，但不依靠 Git 操作删除用户运行数据。
- 正式技术文档继续由 Git 管理；不使用笼统 `/docs/` 规则隐藏公开文档。
- `runs/` 中等待人工选择的候选以及晋升后明确要求保留的评测候选不由 job 清理器处理。

### AudioMiner

- `docs/` 保持忽略。
- 显式忽略 `/venv/`、`/.venv/`、`/.idea/`、测试缓存和 Python 字节码，避免依赖全局 Git 配置。
- 不改变素材输出目录下 `.cache` 的现有成功压缩与失败恢复策略。

## README 信息架构

### AudioMiner README

README 面向第一次安装的用户，按以下顺序组织：

1. 产品模式：独立素材挖掘与 AudioClone Studio 完整模式；
2. 系统要求与 AudioMiner 独立环境安装；
3. 单独使用素材挖掘 GUI/CLI；
4. 获取 voice-pipeline、建立独立训练环境和准备预训练权重；
5. 在设置中连接训练模块并验证握手；
6. 素材挖掘、训练、评测、试听、晋升和推理的完整工作流；
7. 模型、数据集、jobs、runs、outputs 和缓存的实际存储位置及清理规则；
8. 常见启动、环境、权重、断点继续和空间问题。

### voice-pipeline README

`README.md` 作为简洁入口，只保留项目能力、架构边界、安装、权重检查、最短训练流程、与
AudioMiner 的关系及文档导航。

`README_使用指南.md` 作为操作手册，按以下顺序组织：

1. 环境安装与命令注册；
2. 预训练权重目录和验证；
3. `data.list` 与训练配置；
4. 完整训练及单阶段命令；
5. 失败阶段继续；
6. 自动评测、候选试听和人工晋升；
7. 独立推理；
8. jobs、runs、models、outputs 的生命周期和磁盘占用；
9. 常见错误排查。

早期算法设计和兼容性细节留在正式 `docs/` 专题文档，不在入口 README 重复展开。

## 实现范围

AudioMiner 新增一个小型 job retention 模块，复用现有 job/event JSON 结构和 recovery 的
安全校验思路，不引入新依赖。GUI 启动与 ModuleProcessController 终态路径调用同一清理入口。

voice-pipeline 只调整忽略规则、取消跟踪历史 jobs，并重写入口文档；现有训练、评测、晋升和
run 清理算法不因本任务改变。

## 验证

自动测试至少覆盖：

- 活动与无终态 job 保留；
- 等待人工晋升的候选 job 保留；
- 48 小时边界；
- 每目标人只保留最新失败 job；
- 晋升完成和推理完成 job 删除；
- 损坏 JSON、符号链接和越界路径不删除；
- 清理异常不阻断 GUI；
- Activity 只收到汇总事件；
- 两仓忽略规则不再允许 jobs、日志、环境和缓存进入 Git。

完成实现后运行两个仓库的完整测试，并用 `git ls-files` 检查不存在运行时产物。README 中的
主要命令必须与实际 CLI `--help` 和模块握手结果一致。
